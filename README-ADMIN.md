# NEXUS: админка, роли, OTA (Supabase)

## 1. Установка
1. Скопируйте файлы из архива поверх проекта (корень проекта = папка, где лежит `main.js`).
2. `npm install` (добавлены `@supabase/supabase-js` и `electron-store@8`).
3. Откройте `supabase/schema.sql`, **замените `CHANGE_ME_NOW`** на пароль главного админа `kostlim`
   и выполните скрипт целиком в Supabase → SQL Editor. Если схема уже выполнена раньше, достаточно `supabase/add-login-check.sql` (одна функция для показа пункта меню).
4. Запустите приложение: при старте оно само создаст `kostlim` (если его нет), запишет сессию устройства и проверит обновления.

## 2. Вход в админку
Только в приложении (в браузере/на телефоне её нет).
1. **Профиль → карандаш → поле «Логин»**: впишите логин админа (например `kostlim` или логин друга). Библиотека и остальные данные профиля не затрагиваются.
2. Если такой логин есть среди админов, в меню профиля (клик по аватару) над «Настройками» появляется пункт **«Админ-панель»**. Если логина среди админов нет, пункта нет.
3. Клик по пункту открывает вход: логин подставлен, вводится только пароль. Сессия запоминается примерно на 11 часов, потом пароль нужно ввести снова.
4. Других способов открыть панель нет (горячие клавиши и клики по логотипу убраны).

Права дают только пароль и Supabase: само по себе совпадение логина ничего не открывает.
- Главный (superadmin): статистика, API, администраторы (с переключателем роли), публикация обновлений.
- Админ (admin): статистика и переключение API.

**Как дать доступ другу:** войдите как `kostlim` → «Администраторы» → «Добавить» (логин и пароль, роль «Админ»). Другу достаточно вписать этот логин в свой профиль.

## 3. Выпуск обновления (из админки, без GitHub)
Один раз выполните `supabase/add-release-upload.sql` в Supabase → SQL Editor (создаёт хранилище для файлов и функции выбора версии).

1. Поднимите версию в `package.json` (например, `3.3.15`) и поправьте файлы проекта.
2. Админка → **Обновления** → **«Выбрать папку с файлами»** → укажите папку проекта (где лежат `package.json` и `main.js`, у вас это `source`).
   NEXUS сам собирает `app.asar` (код, интерфейс, ресурсы, иконки, библиотеки), проверяет, что все обязательные файлы на месте и в `main.js`/`lib` нет синтаксических ошибок, считает SHA-256, загружает файл в Supabase Storage и публикует релиз.
   Если в папке нет `node_modules`, библиотеки берутся из установленного NEXUS.
3. Впишите «Что нового», нажмите **«Загрузить и опубликовать»**. С галочкой «Сразу выдать всем» окно «Обновить сейчас» появится у всех в течение 20 минут.
4. Можно выбрать и готовый файл: `.asar` (версия читается изнутри), `.zip` или `.exe` (версию укажите вручную, либо она берётся из имени файла).

**Выбор версии.** В списке релизов у любой версии есть кнопка «Выдать всем»: именно её получат пользователи. Для более старой версии это откат. «Вернуть авто» снова раздаёт самую новую.

**Ограничения.** Файл до 50 МБ (лимит бесплатного Supabase Storage). Для файла больше 50 МБ есть блок «Вручную по ссылке» (GitHub Releases и т.п.). Версия электрона (сам Electron) в `app.asar` не входит: если меняете версию Electron, выпускайте `.exe`-установщик.

## Обновления у пользователей (OTA)
- Приложение раз в 6 часов спрашивает таблицу `app_releases`, выбирает самую новую версию (числовое сравнение: 3.3.10 новее 3.3.9) и, если она выше установленной, показывает окно «Обновить сейчас».
- Файл скачивается по https, проверяется SHA-256 (без хэша обновление не ставится), затем скрипт заменяет `resources/app.asar` и запускает NEXUS заново. Старый файл сохраняется как `app.asar.bak`.
- Версия релиза должна совпадать с версией внутри файла (`package.json`). Если не совпадёт, приложение не будет предлагать тот же релиз по кругу.
- Публиковать релизы может только главный админ. Но ссылка и список релизов читаются публичным ключом: скрыть их от пользователей нельзя, иначе приложение само их не скачает.
